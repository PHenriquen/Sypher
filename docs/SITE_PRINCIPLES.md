# Sypher website principles

The site should feel like a small technology organization with a coherent portfolio, not a creator channel, generic startup template or list of unrelated side projects.

## Transferable patterns from comparable sites

### Anthropic — thesis first, structure second

Anthropic's public site leads with what the organization is trying to accomplish, then separates product, research, engineering and company material into clear destinations. The useful principle for Sypher is hierarchy: explain the parent thesis before asking a visitor to understand every project.

Apply to Sypher:

- open with one precise sentence about what Sypher builds;
- use divisions as navigation/organization, not as six competing hero brands;
- let project pages provide evidence that the thesis is real;
- keep founder/personal material subordinate to the company/product story.

Reference: https://www.anthropic.com/

### Vercel — proof through concrete work

Vercel's customer and partner pages make capabilities legible through shipped outcomes and specific projects instead of long capability claims. For Sypher, project cards should eventually show one meaningful proof point: prototype state, working feature, measurable result, demo or repository.

Apply to Sypher:

- prefer `what exists now` over aspirational feature inventories;
- surface project status explicitly;
- distinguish research/prototype/product instead of implying everything is production-ready;
- use screenshots, demos and technical notes as the portfolio matures.

Reference: https://vercel.com/customers

## Information architecture rule

The visitor should be able to answer these questions in order:

1. What is Sypher?
2. What kinds of systems does it build?
3. What has actually been built?
4. Which project/division should I inspect?
5. Who is behind it?

If the homepage makes the visitor decode division names before question 1 is answered, the hierarchy is wrong.

## Visual rule

Individual projects may have strong identities, but the parent site supplies the frame: typography, spacing, navigation, neutral surfaces and endorsement treatment. Project accent colors can enter locally without repainting the entire corporate interface.

This lets Illume, Nodi, SincroHub, Manopla and Réquiem stay recognizable while still reading as one ecosystem.

## Content rule

Every project page should converge on the same small set of facts:

- one-sentence purpose;
- current status;
- problem or experience it targets;
- what is already implemented;
- next meaningful milestone;
- repository/demo when appropriate;
- parent division endorsement.

Avoid invented metrics, fictional clients, fake release dates or language that turns prototypes into finished products.
